# crimes@0.25.0 — the honest denominator

A scanner's report is a fraction, and `crimes` has never shown you the
bottom half.

`0.23.0` and `0.24.0` were scoring-model internals: real, measured, and
hard to care about from outside the repo. This release is about the
boundary between what the tool looked at and what it didn't — and about
the tool being willing to say which is which. Six streams, all instances
of one sentence.

**Every finding count below is measured on real repositories**
(`airflow` 9,924 findings, `mlflow` 6,468, `pydantic` 487, `cal.com`
4,633, `hono` 377), and every number the backlog claimed was re-derived
before it was built on. Four turned out to be wrong.

---

## 1. It scanned things it shouldn't, and never said so

Two defects, one footgun.

`mergeConfig` did `exclude: override.exclude ?? base.exclude`. Setting
`exclude` at all inherited **nothing** from the defaults — and fell
further behind on every release that added one. This repository's own
config had done exactly that: it missed the 11 lockfile and `tsconfig`
patterns added with the `.json`/`.yaml` includes, and reported
`pnpm-lock.yaml` as a **high** `large_file` at 5,469 lines, in the repo
of the tool whose `CLAUDE.md` says "Defaults exclude … lockfiles".

Worse, `crimes init` — the documented first-run command — **hand-copied
9 of the 20 default patterns**, under a comment promising it "must never
make crimes see less than it would with no config at all". Every
lockfile pattern was missing. There is a test suite named
*"generateConfig does not narrow the scan below zero-config"*; every
test in it checks `include`, and none checks `exclude`.

**`exclude` is now additive**, deduped, with `excludeDefaults: false`
restoring the old wholesale replacement — the only way to *un*-exclude
something the defaults drop. `assets.exclude` carried the identical
contract one field away and is fixed the same way under the same flag.
`assets.include` stays on replace: widening what you look at is a
different failure from narrowing what you skip. `crimes init` now
derives from the constant instead of restating it.

This repository's config drops from 28 patterns to the 8 that are
actually repo-specific, and scans identically.

## 2. It charged things it never established

`sync_io_in_hotpath` says a blocking call is costing you a worker. On
airflow, **227 of its 811 findings were in files carrying an
`if __name__ == "__main__":` guard** — one-shot developer scripts with
no worker to hold and no event loop to stall.

Three candidate signals had already been tried and rejected, all three
defeated by the same file,
`task-sdk/src/airflow/sdk/execution_time/task_runner.py`. The third —
*"every same-file call path starts inside the guard, in a module nothing
imports"* — was on record as **the signal that would work**. Tracing it:

```
_send_error_email_notification ← finalize ← main ← guard
_handle_trigger_dag_run        ← run      ← main ← guard
```

`finalize` and `run` have no other same-file caller, and crimes reports
the module at 0 direct importers. **It exempts both findings, which are
the two the remediation doc says are correctly reported.** Three for
three.

What separates the file is that the repository *mentions* it 42 times,
including `mock.patch("airflow.sdk.execution_time.task_runner.startup")`
— a string no import graph can see. So the question is not "who imports
this?" but **"does anyone mention it?"**, counted textually across
imports and dotted string literals, and the bar is zero.

| repo | `sync_io_in_hotpath` | after | of the detector | of the report |
|---|---|---|---|---|
| airflow | 811 | 680 | **−16%** | −1.32% |
| mlflow | 402 | 347 | −14% | −0.85% |
| pydantic | 17 | 11 | −35% | −1.49% |

`task_runner.py`'s two findings are **still reported**. Everything
suppressed on airflow is in `scripts/` (105), `dev/` (22) and
`devel-common/` (4).

## 3. It now skips what a repo has already disowned — and files a receipt

A directory a repo excludes from its own linter, coverage run and
spell-checker is one it does not maintain. pydantic's `pydantic/v1` is
named by all four of its tools and regenerated by `make update-v1`:
**85 findings, 17.5% of pydantic's whole report.**

This turns a config file into a silent-suppression mechanism, and the
project has six prior instances of apparatus that failed closed on
correct input. Three rules, none negotiable:

- **Named tables only.** airflow's `pyproject.toml` carries
  `exclude = ["*"]` under `[tool.hatch.build.targets.sdist]` at line
  589. A reader honouring "any `exclude`" reports airflow as completely
  clean. There is an integration test for that exact shape.
- **Exact keys, not prefixes.** `[tool.coverage.report] skip_empty =
  true` and `[tool.uv] exclude-newer = "4 days"` are a boolean and a
  duration. Meanwhile codespell's `skip` legitimately *is* a
  comma-separated string, so "reject all strings" is not the rule
  either.
- **When in doubt, exclude nothing.** Missing an exclusion costs noise;
  inventing one costs silence.

And the property that makes it shippable: **corroboration**. A path is
skipped only when **two or more independent tools** name it. Across the
entire corpus that is exactly one directory — mlflow's ruff-only list
and drf's codespell-only list corroborate at 1 and are left alone.

```
pydantic  487 → 402   −85, −17.5%
airflow   unchanged, no warning
mlflow    unchanged, no warning
```

Every skipped file is accounted for, aggregated by the pattern that
authorised it:

```
[files_excluded_by_tooling] pydantic/v1 — 26 files
  26 files under pydantic/v1 were skipped because this repository's own
  tooling excludes them. Findings in them are absent, not zero.
  → Set "honourToolingExcludes": false in crimes.config.json to scan it anyway.
```

`[tool.mypy]` is **deliberately unsupported**: its `exclude` takes
regular expressions where pyright's takes globs, and reading one as the
other is precisely the misread the feature is built to avoid.

## 4. It disagreed with itself

`commented_out_code` ships twice. The `language-js` variant always
appended a block hash; the universal one appended it only when a file
held more than one block.

That is not merely a difference — it is **unstable**. A lone block's
hash was discarded, so the moment an unrelated second block appeared
anywhere in the same file, both findings gained discriminators and *the
first one's fingerprint changed because of a finding that is not it*. A
`crimes ignore` entry a user had already written silently stopped
matching.

Unified toward always identifying a block. Churn measured before
choosing: 43 findings this way, 67 the other. **42 fingerprints moved on
the corpus, finding counts identical everywhere, only
`commented_out_code` touched.**

Auditing that pair raised the general question, and the answer is worse
than the two known cases: **of the 8 charges implemented in both packs,
only `large_function` agrees.** Three kinds of divergence —

- different constants for the same shape;
- **different shape**: `circular_dependency` and `deep_import` express
  no intrinsic on the universal side, so they take a *flat* default
  while Python ramps. An 8-module Python cycle reaches **0.92**; the
  identical TypeScript cycle is pinned at **0.45**. Universal
  `deep_import` sits at **0.30** — `NEUTRAL_INTRINSIC` itself, the value
  `0.23.0` was written to stop findings falling back to;
- conditions present on one side only.

In a polyglot repo, `crimes` has been ranking the same defect by the
language it is written in. Reported, **not fixed**: the direction is
inconsistent, so no single offset corrects it, and seven simultaneous
scoring changes in one baseline would be unattributable.

What *did* ship is the mechanism fix. The formula was already universal
— 14 detectors inlined `round(Math.min(base + (n-1)*step, cap))` by hand
while the Python slate factored it. There is now one `intrinsicFrom`,
and a **standing gate** that fails on any cross-pack ladder
disagreement not listed with a reason. Proven findings-neutral on 5,164
findings: zero added, removed, or rescored.

## 5. The instrument had a 15× phantom in it

`mean_ndcg_deep`, the headline ranking number, averages whichever
scenarios sit on a fixture emitting at least `DEPTH_FLOOR` findings.
**That membership is an input to the metric, and nothing reported when
it changed.**

Fixture `01` emitted **42 findings against a floor of 40**, and carried
**21 of the 28 deep scenarios — 75%**. Losing three findings from it
would drop 21 scenarios out at once and move the headline
`0.3530 → 0.4863`: **+0.1333 with no scoring change at all**, against a
largest-ever real movement of `+0.0089`.

All nine stored baselines are clean — fixture `01` has sat at exactly 42
throughout. That is stability by luck: nothing had removed a finding
from `messy-ts-app` in nine releases, and this is the release that
removes findings.

**The fix was free.** Fixture depths are
`[1, 3, 4, 5, 9, 13, 42, 55, 92, 99]` — a 28-finding empty gap, with the
floor *perched* rather than centred. Every floor in `[14, 42]` selects
the same four fixtures:

```
mean_ndcg_deep  0.3530 → 0.3530   byte-identical
scored_deep     28     → 28       same scenarios
fixture 01 headroom  2 → 14
```

All nine baselines stay comparable. Two standing diagnostics keep it
honest, and **the guard earned itself on its first real use**: adding
scenarios later in this release moved the headline `0.3530 → 0.3498`,
which reads as a regression and is not one —

```
⚠ THE DEEP SET CHANGED. The delta above is NOT a before/after.
  entered (2): bugfix-04-unbounded-fanout, review-04-swallowed-errors
  headline moved -0.0032, but on the 28 scenarios deep in both runs
  it moved +0.0000.
```

## 6. And the instrument can now see this release

Only 3 of 28 deep scenarios labelled any of the detectors `0.23.0`
un-suppressed, and **11 of the 28 were referenced by no scenario at
all**. Two of them already fired on a deep fixture and simply had no
scenario. Fixture 14 is new because **A was unmeasurable**: no fixture
had a `pyproject.toml`, so neither `evals:ranking` nor the agent run
could see the tooling-exclude feature.

```
deep scenarios labelling a differentiated detector   3/28 → 5/30
of the 28 referenced by any scenario                 17   → 19
fixture 01 share of the deep aggregate               75%  → 70%
```

`context-14-what-was-not-scanned` is the first scenario that asks an
agent about the **denominator** rather than the findings: what was
skipped, on whose authority, and whether the report is a complete
picture.

## Four things the backlog was wrong about

The most useful output of this round, as usual.

1. **B's headline is 28% of a *detector*, not of a report.** All three
   figures reproduce exactly, but in report terms they are 2.29% /
   1.36% / 1.44%. The two rows of the backlog's impact table were in
   different units under one column heading.
2. **The signal named as the one that would work, doesn't.** It exempts
   the counter-example it was written to preserve.
3. **pydantic's third exclusion is `[tool.pyright]`, not mypy** — there
   is no `[tool.mypy]` table in the file. Load-bearing, because their
   `exclude` keys take different languages.
4. **"A `coverage.warnings[]` entry per skipped path" contradicts the
   shipped contract**, where `subject` is documented as never a file
   path because it is the aggregation key. Taken literally it emits 85
   warnings on pydantic alone.

## The eval baseline, and what it can and cannot say

`0.25.0` ran the full matrix: **102 combinations** (51 scenarios × 2
agents), up from 96 because this release adds three scenarios.

```
claude  0.82 → 0.84
codex   0.61 → 0.58
```

**Do not read those as a before and after.** The scenario set changed,
which is the same population trap this release fixed on the ranking
metric — so the honest comparison is the 48 scenarios present in both:

| agent | headline | on the stable 48 |
|---|---|---|
| claude | +1.3pp | **+0.0pp** (0.823 → 0.823) |
| codex | −2.5pp | **−5.1pp** (0.608 → 0.557) |

Claude's entire headline movement is the three new scenarios; on the
identical 48 it is unchanged to three decimal places. Codex is *worse*
than its headline suggests, and −5.1pp is outside its stated ±3pp noise
band.

**It is not a regression, and there is a decisive reason.** All **96
stable pairs received a byte-identical `scan_context`** — the agents saw
exactly the same crimes output as at `0.24.0`, because no fixture's
findings moved (`evals:ranking` reported "no scenario moved" at every
step of this release). Whatever changed, it was not the input.

So this run is a **free repeat sample**, in the sense of
`evals/README.md` § "A second, accidental repeat sample", and it
measures agent variance directly:

```
claude  16 of 48 scenarios moved with identical input, net  +0.0pp
codex   16 of 48 scenarios moved with identical input, net  −5.1pp
```

Codex's moves run in both directions — `bugfix-01-messy-ts-app` 0/2 → 2/2
and `bugfix-13-polyglot-plan-drift` 0/4 → 2/4 alongside
`review-05-permission-and-parallel` 4/7 → 0/7. **The stated ±3pp band
for codex is too narrow**, and the honest conclusion is that a
single-sample `structural_pass_rate` delta of this size means nothing
about the product. That is a finding about the instrument, not a result
about the release.

Which is the second thing to say plainly: **`structural_pass_rate`
cannot see most of this release.** It matches detector ids in an agent's
response, and A and B move findings on real repositories while barely
touching the fixtures. The pydantic and airflow numbers above are the
evidence; the agent run is a guard confirming nothing broke, and it
confirms that.

The deterministic metric, which *can* be quoted:

```
mean nDCG (deep)  0.3530 → 0.3498   headline
                          +0.0000   on the 28 scenarios deep in both runs
```

## Compatibility

`schema_version` stays **`0.7.0`** — every schema change is additive: a
new `coverage.warnings[].kind`, and two new optional config keys
(`excludeDefaults`, `honourToolingExcludes`).

**Fingerprints move for one population**: `commented_out_code` findings
in single-block non-JS files (42 on the corpus). If you have `crimes
ignore` entries on those, re-add them.

Tests **2,221 → 2,313**.
