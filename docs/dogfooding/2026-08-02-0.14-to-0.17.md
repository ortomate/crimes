# Dogfooding round — `crimes` 0.14 → 0.17 against real codebases

**Date:** 2026-08-02
**Build under test:** `crimes` 0.17.0 (`schema_version` 0.4.0), built from source.
**Protocol:** [`2026-08-02-protocol.md`](./2026-08-02-protocol.md)
**Friction log:** [`2026-08-02-log.md`](./2026-08-02-log.md)

The round planned in `da3a894` was never executed. Four releases of
detector surface had never run against code outside their own fixtures.
This is that round, widened from precision calibration to a usefulness
verdict.

## 3. Verified defects

Every item here was reproduced by the orchestrator, not accepted from a
subagent report.

### 3.1 BLOCKER — source under a dot-directory is silently skipped and reported clean

`packages/core/src/discovery/files.ts:25` hardcodes `dot: false`. There
is no config or CLI override anywhere in `discovery/`.

Minimal reproduction, identical 8-line Python file:

```
as visible.py             → "2 findings across 1 file"
as .agents/skills/bad.py  → "No crimes detected. Suspiciously clean."   EXIT 0
```

In the wild: `ebg` keeps all 62 of its `.py` files under `.agents/`.
`coverage.files_by_language` had **no `py` key**, while `packs_loaded`
still advertised `language-py`. Renaming `.agents` → `agents` moved the
scan from 759 to 967 findings and surfaced a real
`cross_language_concept_alias_drift` that the true scan reported as zero.

`.github/`, `.claude/`, `.config/`, `.server/` are all common. This is
the worst failure mode a scanner can have: a confident all-clear, a
cheerful message, and a zero exit code on code it never opened.

### 3.2 BLOCKER — `crimes context` ids do not resolve in `crimes explain`

```
$ crimes context src/MetricsGrid.tsx   → id=crime_00001
$ crimes explain crime_00001           → file: src/server/migrations.ts
```

`context` numbers its findings locally from 1; `explain` resolves against
the global scan ordering. They agree only when the file happens to rank
first. `context <file>` → `explain <id>` is the documented pre-edit agent
workflow and the core of the agent-native positioning. An agent
following it receives a detailed, confident rationale for a different
finding in a different file, exit 0, no warning.

### 3.3 BLOCKER — `cross_language_route_drift` can only ever see a Python backend

`packages/core/src/detectors/cross/route-drift.ts:124` skips any file
whose `pack !== "language-py"`. A TypeScript backend is invisible in
principle, not by calibration.

`ebg` has 22 `app/api/**/route.ts` handlers exporting 23 verbs against 9
client `fetch("/api/…")` call sites — a textbook drift surface the
detector cannot flag.

It fired **once** in the whole corpus — on airflow, a Python backend.
Zero on zulip, also Django + TS. So the detector works, narrowly, on the
one shape it permits, and structurally excludes the most common polyglot
shape in the JS ecosystem: a TS/Next.js backend with a TS client.

`coverage.by_package` is additionally gated on `MIN_PACKAGES = 2`
manifest dirs. It is present on airflow and hono, and absent on ebg —
the repo shape the feature's own motivating example describes ("70%
TypeScript with one Python service"), because the Python subtree has no
`pyproject.toml`.

### 3.4 BLOCKER — the 0.17.0 fingerprint fix did not fix the bug class

v0.17.0 broke the wire format to fix fingerprint collisions, reporting
"Self-scan collisions: 3 → 0" and "the bug is in the fingerprint
function's inputs, so it gets one general answer."

The general mechanism shipped. It was wired into **2 detector files**
(`exact-duplicate-block.ts`, `magic-domain-literal-scatter.ts`) — the
instances the self-scan surfaced. The self-scan was a biased sample:
this repo has few test files and little commented-out code.

Measured on real repos:

| repo | findings | unique fingerprints | lost to collisions |
|---|---|---|---|
| hono | 377 | 288 | **89 (24%)** |
| zulip | 3759 | 3433 | **326** |
| buildfest | 1556 | 1362 | **194 (12%)** |
| pydantic | 578 | 552 | 26 |

Worst groups: `commented_out_code` ×12 (empty symbol),
`duplicate_component_shape` ×10, `large_function` ×9 (`describe
callback`), `weak_test_signal` ×8 (empty symbol).

These are exactly the consequences 0.17.0 named as justifying a wire
break. `crimes ignore` on one `commented_out_code` finding silently
suppresses up to 12. `crimes diff` is blind to 24% of hono's findings.
Empty `symbol` is the tell.

### 3.5 BLOCKER — `crime_NNNNN` ids are not stable across runs

Two back-to-back scans of hono at the same SHA produced an identical
finding multiset in a **different order**. Ids are positional, so five
ids changed identity: run A `crime_00024` = `large_file` on
`secure-headers.ts`; run B `crime_00024` = `hardcoded_localhost` on a
benchmark. Suspected cause is the clock-derived `recency` score drifting
0.71 → 0.70 and flipping a sort tie.

0.17.0 fixed evidence-string determinism. Finding *identity* ordering is
still clock-dependent, and `crimes explain <id>` does not survive a
re-run.

### 3.6 BLOCKER — `agent_risk` has collapsed into size

15 of the top 20 findings by `agent_risk` on `ebg` are `large_function`
/ `large_file`. Nothing from the 0.16 slate appears, despite
`parallel_destination` firing 52× and `orphaned_destination` 39× in that
repo.

`CLAUDE.md` states `agent_risk` "is the differentiator and must not be
collapsed into severity". Observably it is a length ranking. This is the
score the entire product thesis rests on.

### 3.7 BLOCKER — `.gitignore` is not respected

`CLAUDE.md` § Stack decisions states: "File walking: fast-glob + `ignore`
(respect `.gitignore`)." It does not.

Reproduction from scratch:

```
/tmp/gitig3/.gitignore              → "generated/"
git check-ignore generated/big.ts   → generated/big.ts   (ignored)
crimes scan .                       → "2 findings across 1 file · 1 high"
                                    → generated/big.ts: God Function, God File
```

The gitignored file is the *only* file in the report.

In the wild, on buildfest: `migrate-output/` is line 8 of `.gitignore`
and a verbatim copy of `apps/airquote`. It produced 100 findings
directly and 229 more citing it — **323 of 1556, 20.8% of the entire
report** — and **136 of 158 (86%) `exact_duplicate_block` findings**. It
also appears in `coverage.by_package`.

Duplication detectors are maximally vulnerable to build output, and
build output is exactly what `.gitignore` names. This stayed invisible
because the hardcoded default excludes cover `node_modules`, `dist` and
`.next` — the common cases — so only project-specific ignore rules
expose it.

Together with §3.1, `crimes` both scans what it shouldn't and skips what
it should, and reports neither.

### 3.8 BLOCKER — `large_file` counts total lines + 1 and calls it "non-empty"

| file | crimes claims | real total | real non-blank |
|---|---|---|---|
| `pydantic/fields.py` | 1914 | 1913 | 1654 |
| `pydantic/types.py` | 3336 | 3335 | 2647 |
| `pydantic/networks.py` | 1371 | 1370 | 1084 |

Exactly `total + 1` every time, labelled "non-empty lines" — overstating
the true non-empty count by 16–26%.

**It manufactures findings.** Of 109 `large_file` findings on pydantic,
**11 (10%) would not fire at all** on the true count: `_migration.py`
(claimed 318, real 298, threshold 300), `_dataclasses.py` (316/253),
`v1/env_settings.py` (351/290), five `pydantic-core/*.rs`, and two
markdown files — so 0.17.0's `docs` shape inherits the bug
(`docs/migration.md`: claimed 1168, real 889, threshold 1000).

`large_file` is the second-highest-volume detector in the corpus (779
findings). The `lines` field and every "N× the threshold" ratio are
wrong by the same amount.

### 3.9 BLOCKER — `scan` on a nonexistent path exits 0 and reports clean

```
$ crimes scan /tmp/this-path-does-not-exist-xyz
CRIME SCENE REPORT
repo: this-path-does-not-exist-xyz  ·  0 findings
No crimes detected. Suspiciously clean.
EXIT=0
```

The JSON form is equally well-formed: valid `schema_version`, empty
`findings`, `files_total: 0`, exit 0. A path typo in CI is a permanently
green gate. `verdict` and `explain` both correctly exit 2 on bad input;
`scan` is the outlier.

### 3.10 BLOCKER — test-scope classification is structurally inert on Python

`packages/core/src/config.ts:17`:

```ts
export const DEFAULT_NON_DOMAIN_PATTERNS: string[] = [
  "scripts/**", "examples/**", "fixtures/**", "public/**",
  "**/__tests__/**",
  "**/*.test.{ts,tsx,js,jsx}",
  "**/*.spec.{ts,tsx,js,jsx}",
];
```

No `tests/**`, no `test_*.py`, no `*_test.py`. Measured: **every finding
is `tier: "domain"`** — pydantic 578/578 including 118 under `tests/`,
drf 104/104, zulip 662 test-file findings all `domain`.

The sharp part: `crimes` already has the right classifier.
`util/test-files.ts:23` matches `test_[^/]+\.py$` and
`.*_test\.(?:py|go)$`. `tier` uses a third, glob-based, JS-only
mechanism. `classifyScope` is imported by exactly 4 detectors, all
0.16.0 JS-side — zero Python and zero universal detectors consult it.

`CLAUDE.md` presents `util/scope-class.ts` as "one answer to generated /
vendored / migration / fixture / test / config / production". There are
three answers, and the one wired into scoring cannot see a Python test.
Test files are 62–64% of both pydantic and drf.

### 3.11 BLOCKER — silent, nondeterministic finding loss under fd pressure

At `ulimit -n` ≥ 48 buildfest output is byte-identical to baseline —
the 0.17.0 bounded pool is correctly sized and holds. Below ~48 the scan
silently reports fewer findings, **nondeterministically**: three runs at
`ulimit -n 40` on an unchanged tree gave 1522 / 1535 / 1543. Every one
exited 0, empty stderr, an *identical* `coverage` block, `summary.high`
pinned at 187, while ~11% of the report vanished.

Root cause is not `indexes.ts`. `ast-hash/function-index.ts:72-79`:

```ts
try { source = await readFile(abs, "utf8"); }
catch { return hits; }   // EMFILE becomes "this file has no functions"
```

Same shape at `jsx/shape-index.ts:65-66`. The bare catch cannot
distinguish `ENOENT` from `EMFILE`, so each exhaustion silently deletes
one file from the duplicate corpus — partial and racy, strictly worse
than the all-or-nothing `undefined` `indexes.ts` was designed to
produce. Margin between correct and silently wrong: **8 descriptors**.

### 3.12 `crimes context` drops exactly the findings an agent cannot derive

On `JobDetail.tsx`, `scan` reports 12 findings and `context` reports 11.
The missing one is `duplicated_policy` — a cross-file finding, i.e. the
single class of thing an agent reading that one file could not work out
for itself. `context` is the product's best surface and its whole
purpose is to brief an agent before an edit.

Also: on a pnpm workspace, `context app/src/middleware.ts` prints
`file: src/middleware.ts` — a path that does not exist, and is plausible
because the repo has a real top-level `src/`. It analysed the right file
and displayed an unopenable path.

### 3.13 SYSTEMIC — detectors with OR-triggers print evidence for the condition that did not trip

A detector fires on `A || B` but builds its summary and leading evidence
from `A` unconditionally. When only `B` tripped, the finding presents a
measurement that **passed** as if it were the reason.

- `py/large-function.ts:75-108` — fires on `tooLong || tooDeep`, always
  says "is N lines … At this size an agent must read the whole body".
- `todo-density.ts:40` — `if (matches.length < 3 && density < threshold)
  return []`, then prints "4.2 markers per 1k LOC (threshold 10)".

Real output: pydantic `get_strict` — **14 lines, threshold 50** — charged
as a God Function. `deep_update` — 9 lines. drf: 12 of 50 sampled cards.
zulip: 26, 19, 23 lines against a 50-line threshold.

All three blind judges independently used the word "contradicted". The
underlying signals (deep nesting, TODO count) are legitimate; the message
destroys them. This is the round's cheapest fix and its most expensive
trust cost.

## 4. False positives in full

The detectors below are not miscalibrated at the margin — they assert
things the code in their own evidence window refutes.

**`pass_through_abstraction` fabricates call chains from name
collisions.** zulip: reported `get_services` "forwards through 5 layers
across 5 files". The body is `return services.get(bot_id)` — one line.
The chain was assembled from unrelated `get` methods in
`markdown_config`, `message_list`, `sub_store`. 19 findings, all one repo.

**`weak_test_signal` does not follow assertion helpers.** 42 judged, 0
act. drf-0033: "11 of 11 test functions assert nothing" — every test
routes through `_resolve_urlpatterns`, which the card itself prints
asserting on three attributes. drf-0037: 10 tests call
`_assert_datetime_rendering`, shown ending in `self.assertInHTML`. It
counts `self.assert*` but not `self.fail`, not
`model_dump_json(warnings='error')`, and treats `@pytest.mark.benchmark`
functions as assertion-free when measuring is their entire purpose.
Extract-a-shared-assertion-helper is among the most common test idioms
there is; the detector reads it as the absence of testing, and is most
wrong on exactly the well-factored suites it should be quietest about.
619 findings corpus-wide.

**`boolean_naming_drift` flags names that cannot be renamed.** 48 judged,
0 act. Four findings on `atomic = False` inside `class
Migration(migrations.Migration)` — a Django-defined attribute. 18 names
"bound to a boolean expression with nothing saying they hold true/false"
that are Pydantic fields explicitly declared `name: bool`. Names its own
convention clause exempts ("or an idiomatic bare name"): `nullable`,
`plural`, `frozen`, `from_attributes`, `lock_acquired`. On p-limit it
proposes renaming `rejectOnClear` — a public API option, a semver-major
change — at `effort: "quick"`.

**`sync_io_in_hotpath` has no working notion of "hotpath".** 16 judged, 0
act. Fires on a `if __name__ == "__main__"` setup CLI, a Django
management command, a `release/push.py` script, an `@cache`-decorated
once-per-process function, and two calls inside `if
settings.DEVELOPMENT:` next to a comment saying nginx serves the file in
production. On `ebg` it is also a file-level finding wearing a
function's name: 43 findings across exactly 43 files, with `symbol` and
`lines` spanning ranges the named function does not occupy.

**`swallowed_error` does not read the comment that explains the catch.**
Best-performing 0.16 detector at 12.3%, but 20 of hono's 43 cards were
this detector and nearly every one had an explanatory comment or a
visible fallback. It fires where the next line is `throw err`
(hono-0011); where the catch calls three recovery functions; and on
p-limit's `index.js:44`, three lines below a comment reading "We catch
errors here to prevent unhandled rejections, but the original promise
rejection is preserved for the caller." Its `BEST_EFFORT_FUNCTION_RE`
recognised deliberateness on exactly one hono card while missing an
identical comment two functions above.

**`unbounded_async_fanout` on p-limit** — a library whose entire purpose
is bounding concurrency. Its evidence simultaneously states "collection
source: an awaited call" and "produced by: `Array.from`", about
`Array.from({length: 100}, …)`, then concludes "N is a property of the
data, not of this code."

**Vendored and framework-owned code is treated as domain code.** drf:
three findings on vendored minified google-code-prettify. pydantic: 10
cards target `pydantic/v1/`, the frozen vendored tree. Django's own
mandated `management/commands/*` layout flagged as reaching into
internals. `util/scope-class.ts` is documented as the single answer here
and is not catching vendored trees, framework layouts, or frozen legacy
subtrees. This inflates every downstream count.

## 5. Actionability, separately from correctness

The act-rate table is the actionability measure and it is the report's
core finding. Three observations the precision framing would miss:

**Volume is the product.** 8134 findings across the 9 judged repos;
zulip alone 3759 with 502 high. Airflow, scanned after judging closed,
returned **17,801 findings with 929 high** on 9149 files — of which
`commented_out_code` alone is 8019 (45%) and `deep_import` 3453. Even at
a generous 15% act rate, an airflow maintainer would sift ~15,000
findings to reach ~2,600 worth considering. "Signal over exhaustiveness"
is a stated constraint; at this volume it does not hold, and the two
detectors driving it on large Python repos were not even in the judged
sample.

**Default-view suppression is a file cap, not a finding budget.**
`scan.topFiles: 5`. On hono that compresses 377 → 35 (9% shown). On
p-limit it shows 9 of 10 (90%). The compression is an accident of repo
size rather than a designed budget — the small clean repo, where a
first-time user calibrates their trust, gets no compression at all.

**The loudest outputs are the least reliable.** Judges consistently rated
`crimes context` the most useful command and `scan`'s headline and
`hotspots` the least. On hono, `hotspots` ranks `package.json` #1 at 72%
risk — 14 points clear of anything real — because it churned 29× in 90
days on version bumps. That ranking is backwards from what earns trust
on first contact.

**`--all` is a byte-for-byte no-op in `--format json`** — verified by
identical MD5 on two repos, while the human output advertises "Run with
`--all` to see them."

## 6. Robustness and performance

**Python parsing: PASS.** This is the round's clearest good news. On
`ebg`, 51 of 62 `.py` files produced findings, with positive evidence per
construct: `match` statements bounded correctly and counted case arms as
nesting; walrus across 5 files; PEP 604 across 8. PEP 695 generics,
`type X =`, and `except*` were probed synthetically and parse with
correct symbols and ranges. No parse failures, no crashes, no grammar
errors anywhere in the corpus.

**The zero case: PASS.** On every single-language TS repo, all three
`cross_language_*` detectors and all Python detectors produced exactly
zero. No false positives from either pack. But `coverage.packs_loaded`
lists `language-py` on repos with no Python — it reports what was
*loaded*, not what *ran*, and disagrees with `files_by_language`. Only
the latter is informative, and the protocol's own advice to "check
`packs_loaded`" is therefore wrong.

**Determinism: mixed.** Finding *sets* were reproducible (`ebg`: two runs
byte-identical). Finding *order and ids* were not (§3.5).

**Performance.** Scans are acceptable (zulip: 3588 files in 81s). The
git-touching commands are not: on `ebg`, a 6s full JSON scan sits beside
`hotspots` at 27s, `verdict` at 53s, and `diff` at 62s — the latter to
report "New: 2" without saying which two. `verdict` is pitched as a
CI/pre-commit gate. Three commands run 3–4× wall-clock over CPU.

**No EMFILE, no OOM** on any completed scan. The 0.17.0 bounded-pool fix
held on everything measured so far; the four largest repos were still
running at time of writing.

**A killed scan leaves a 0-byte artefact indistinguishable from a
successful empty one.** Several artefacts were 0 bytes from SIGTERM
(exit 143), not from clean results.

## 7. Ranked recommendations

Not applied. Each is labelled with its cost per `CLAUDE.md` and
`evals/README.md`.

### Fix before anything else — correctness, not calibration

0. **Fix the four silent-wrong-answer bugs as one workstream.** They are
   the same failure: `crimes` knows something is off and says nothing.
   - `.gitignore` ignored (§3.7) — scans what it shouldn't
   - `dot: false` (§3.1) — skips what it should scan
   - nonexistent path → exit 0 "clean" (§3.9)
   - EMFILE swallowed as "no functions" (§3.11)
   Add a single `coverage.warnings[]` and make every one of them
   populate it. No output should ever say "Suspiciously clean" when
   anything was skipped, unreadable, or absent.
   *Cost: schema addition (minor) + four small fixes.*
1. **Scan dot-directories, or say you didn't.** `dot: false` →
   configurable, defaulting to scanning them minus a deny-list. At
   minimum, never print "Suspiciously clean" when files were excluded.
   *Cost: detector-adjacent product change — patch bump + eval re-run.*
1b. **Respect `.gitignore`** — the behaviour `CLAUDE.md` already claims.
   Expect a large finding drop on repos with build output committed to
   ignore rules; buildfest loses 20.8%. *Cost: patch bump + eval re-run.*
1c. **Fix the `large_file` line count** (§3.8). It is counting
   `total + 1` and calling it non-empty. ~10% of `large_file` findings
   are phantom. *Cost: patch bump + eval re-run.*
1d. **Wire Python and universal detectors into `classifyScope`** and add
   Python test globs to `DEFAULT_NON_DOMAIN_PATTERNS` (§3.10). Until
   then no Python finding is ever discounted for being in a test.
   *Cost: patch bump + eval re-run; expect a large scoring shift.*
2. **Make `context` ids resolvable by `explain`.** Either emit global
   ids from `context` or have `explain` accept a file-scoped id.
   *Cost: CLI fix, no schema change.*
3. **Give every multi-finding-per-file detector a discriminator.** Empty
   `symbol` is the tell: `weak_test_signal`, `commented_out_code`,
   `duplicate_component_shape`, `large_function`. Assert fingerprint

## 9. What was deliberately not judged

- **Findings outside the sampling rule.** The rule was "every finding
  from a 0.14+ detector, plus the top 20 by `agent_risk`", randomly
  capped to 50 per repo at seed 20260802 where it overflowed. 426 of
  8134 findings were judged. The cap was applied mechanically, never by
  picking.
- **Five repos still scanning** at time of writing: posthog, mlflow,
  n8n, cal.com, ortomate-studio. Three others (airflow, choreograph.cc,
  mysidekick-cc) completed after the judging sample closed and are
  counted only in the volume and zero-firing analyses, never in an act
  rate. Airflow materially changed one conclusion — the cross-language
  pack is not dead, only nearly so — which is a reminder that this
  corpus is still small enough for one repo to move a headline.
- **The write commands** (`init`, `baseline`, `triage`, `ignore`,
  `feedback`) were exercised only on disposable clones and are reported
  in the friction log, not judged for usefulness.
- **`crimes feedback` was not used to record these verdicts.** The
  protocol called for it. The fingerprint collisions in §3.4 mean
  recording 426 verdicts by fingerprint would have silently merged an
  estimated 10–24% of them. That is itself a finding: **the calibration
  loop cannot currently record the results of a calibration round.**
- **No detector was changed during the round**, per the protocol.
- **Judge disagreements** (26% of cards) are recorded in
  `~/crimes-dogfood/disagreements.json` and were not adjudicated
  individually; the two judges are reported separately throughout rather
  than merged into a single number.

## 10. Assessment

The question was whether `crimes` is genuinely useful. On this evidence:

**Not yet, in its default configuration, on well-maintained code.** Five
mature repos, 203 judged findings, two worth acting on.

But the failure is not that the ideas are wrong. It is that a cluster of
defects is poisoning a large amount of correct work, and they share one
shape: **`crimes` knows something went wrong and says nothing.**

- a walker that skips hidden directories and calls the repo clean
- a walker that ignores `.gitignore` and charges you for build output
- a nonexistent path that returns a well-formed clean report, exit 0
- descriptor exhaustion that silently deletes 11% of findings, racily
- a line counter that reports `total + 1` as "non-empty", inventing ~10%
  of its own findings
- an id scheme that survives neither a re-run nor a second command
- fingerprints that collide on up to a quarter of findings
- summaries that state the opposite of their own evidence
- test-scope classification that cannot see a Python test
- a differentiating score that has quietly become a line count

None of these require rethinking the product, and most are small. What
they have in common is more important than any one of them: the tool's
default response to uncertainty is reassurance. For a product whose
entire pitch is *evidence before judgement*, that is the thing to fix
first — a single `coverage.warnings[]` would surface four of them at
once. `crimes context`, the evidence
blocks, the Python parser, the zero-case discipline, and `verdict`'s
refusal to manufacture drama are all genuinely good and worth building
on.

The honest summary is that the last four releases shipped detector
surface faster than they shipped confidence in it, and the self-scan
that stood in for real-world validation was a biased sample in exactly
the ways a self-scan is always biased. This round is the correction.
